# 玩家统计脚本

`python/player_statistics.py` 使用Python标准库读取本项目已有的完整记录，不加载模型，不需要GPU或新增对局。支持Python 3.10及以上版本。现提供全部22项指标，并保存分子、分母、计量单位及公式。

效率与收支公式已按用户确认的定义实现。以下其余默认口径采用本次提出的方案，可通过参数切换；不把这些默认值解释为所有平台统一的行业定义。

## 使用

在本项目目录运行：

```powershell
$python = 'D:\PycharmProjects\Envirment1\venv\Scripts\python.exe'
$records = 'G:\Documents\Test\batch-100-20261025-175727'

# 当前实验：分别统计四种诅咒角色，跨初始座位聚合
& $python -B python/player_statistics.py --input $records --group-by curse --output "$records/summary/player-statistics"

# 仅统计诅咒3的AI，跨座位聚合
& $python -B python/player_statistics.py --input $records --curse 3 --group-by curse --output .utmp/curse3-statistics

# 按玩家名称选择任意AI；可使用通配符
& $python -B python/player_statistics.py --input $records --name 'Mortal-2' --group-by name --output .utmp/mortal2-statistics

# 选择初始座位0；或用 --model-sha 指定模型SHA256前缀
& $python -B python/player_statistics.py --input $records --seat 0 --group-by seat --output .utmp/seat0-statistics

# 同时输入多个批次、单场目录或match.json
& $python -B python/player_statistics.py --input '记录目录一' '记录目录二' --group-by name --output .utmp/combined-statistics
```

`--group-by` 支持 `name`（默认）、`curse`、`seat`、`model`。`--name`、`--seat`、`--curse` 可重复；同类条件取并集，不同条件取交集。`--name` 为大小写敏感通配符；`--model-sha` 为模型权重SHA256前缀。

本批四个座位使用同一模型，名字 `Mortal-0` 至 `Mortal-3` 对应固定初始座位，诅咒会轮换。研究某种诅咒时用 `--group-by curse`；研究同一模型全部出场时用 `--group-by model`，后者会合并四个座位，形成400个“玩家-整场”观察值，而不是400个独立半庄。

默认只统计 `modelSeats` 中的玩家。`--include-local` 可以包含示例宿主的本地玩家。当前记录格式每场共用一个模型身份；不能凭此格式推断未被记录的逐座位不同权重身份。

## 样本与统计口径

令 `N` 为计入的玩家-本局数，`W` 为实际和牌局数，`D` 为放铳局数，`R` 为成功立直局数，`E` 为荒牌流局局数，`M` 为完整的玩家-整场数。

默认 `N` 包含九种九牌、四风连打等途中流局。当前100场每种诅咒均有 `N=1618`，其中荒牌234局、途中流局557局。`--exclude-abortive` 将途中流局从所有本局类指标的样本中剔除，此时每种诅咒 `N=1061`。平均顺位、被飞率始终以完整整场为单位，不随这个选项改变。

| 指标 | 默认定义 |
| --- | --- |
| 和牌率 | 实际荣和/自摸局数 `W / N` |
| 放铳率 | 放铳局数 `D / N`；一次舍牌被多人荣和仍算一次放铳 |
| 自摸率 | 自摸和牌次数 `/ W`，包含副露自摸及役满自摸；不根据“门前清自摸和”役推断 |
| 立直率 | 成功立直局数 `R / N`；宣言牌被荣和而未成立的不算 |
| 默胡率 | 门前且未立直的和牌次数 `/ W`，包括门前未立直自摸；暗杠不破门前 |
| 流局率 | 荒牌流局局数 `E / N`；默认分子不含途中流局 |
| 流听率 | 荒牌流局结算时本人听牌的次数 `/ E`；不把途中流局当作听牌/不听牌 |
| 副露率 | 至少有一次成功吃、碰、大明杠的局数 `/ N`；加杠延续原副露，暗杠不算，未成立或被覆盖的声明不算 |
| 和了巡数 | 本人和牌巡目总和 `/ W` |
| 平均打点 | 本人和牌得点合计 `/ W` |
| 平均铳点 | 本人放铳损失合计 `/ D`；多家荣和合计本人该次实际损失 |
| 被飞率 | 最终点数小于0的玩家-整场数 `/ M`；0点不算被飞 |
| 平均顺位 | 记录中的最终名次合计 `/ M`；沿用核心的同分顺位规则 |
| 立直放铳率 | 成功立直后发生放铳的局数 `/ R` |
| 立直和牌率 | 成功立直后本人和牌的局数 `/ R` |
| 先制立直率 | 本局第一家成功立直次数 `/ R`；依据事实顺序，不以庄家或平均巡目推断 |
| 立直巡目 | 成功立直宣言牌的本人巡目合计 `/ R` |
| 立直收支 | 立直成立的各局 `Σ(结算后本人点数−开局本人点数) / R` |
| 打点效率 | 和牌率 × 平均打点，即和牌得点合计 `/ N` |
| 铳点损失 | 放铳率 × 平均铳点，即放铳损失合计 `/ N`；以正数表示损失 |
| 净打点效率 | 打点效率 − 铳点损失 |
| 局收支 | 各局 `Σ(结算后本人点数−开局本人点数) / N` |

和牌只按实际 `Ron` / `Tsumo` 结算统计。多人荣和对每个赢家分别记一次和牌；同一个放铳者只记一次放铳。流局中的流满不计入普通和牌，另有原始计数 `nagashi`。

## 打点与收支

默认 `--points base`：

- 平均打点按真实庄闲、自摸/荣和及整百舍入计算赢家收入，排除本场和供托，保留所有役满。
- 平均铳点按放铳者的实际支付账扣除其承担的本场计算。包牌责任人代付时，不能把赢家全部收入都算到放铳者身上。
- 以上两个口径同时用于打点效率、铳点损失及净打点效率。

`--points actual` 改用赢家实际收到的本场/供托收入及放铳者实际支付的本场损失。供托来自桌上牌池，不是当次放铳者额外支付的点数。

**立直收支和局收支始终使用真实净得失，包含立直棒、本场、供托及终局剩余供托分配，不受 `--points` 影响。** 核心的结算 `deltas` 发生在立直棒提前扣除之后，直接用它会漏算立直支出，因此这里使用完整的开局检查点和结算后点数相减。仅有打点效率减铳点损失不能代替局收支：后者还包含被自摸、流局罚符、立直棒和包牌等影响。

## 巡目

按本人第几次出牌回合计数：普通摸牌进入下一巡，吃碰后的出牌也算一巡；杠后补牌不额外增加一巡，多次岭上补牌仍处于同一出牌回合。开局检查点已经含庄家首摸，脚本只处理对应事实一次，不重复计数。

立直取宣言牌所在巡。默认 `--ron-turn current`：荣和取本人最近已进入的回合，第一次本人回合前荣和记为1。`--ron-turn next`：荣和按“本人已舍牌张数+1”计巡。自摸始终使用当前本人回合。逐局导出同时保存本人摸牌数和舍牌数，便于复核。

## 切换定义

```powershell
# 排除途中流局，并让“流局”分子包含所有被计入的流局
... --exclude-abortive --draws all

# 自摸次数除以总局数
... --tsumo-denominator rounds

# 默胡仅取门前未立直荣和，分母也改为荣和数
... --dama closed-nonriichi-ron

# 含本场/供托的打点；荣和按下一出牌巡计算
... --points actual --ron-turn next
```

每次输出都保存实际选择的定义。条件分母为0时输出 `null` / CSV空白，而不伪装为0%。例外是有对局但零和牌/零放铳时，对应效率为0，因为其累计得失确实为0。

## 输入质量与版本隔离

输入是本项目的 `match.json`、`events.jsonl` 和 `rounds.jsonl`，不是通用mjai、天凤或雀魂牌谱解析器。完整成功事实和开局点数不可缺省；不接受只有最终比分或局中途才开始记录的检查点。

默认仅纳入已完成且有统计资格的 `experiment` 场次。失败、截断、仍在运行及其他用途的场次会在 `sources.csv` 明确列出排除原因，不静默消失。`--purpose validation` / `--purpose benchmark` 可显式选择相应完整场次，允许重复指定用途；它们不会被改写成正式实验样本。

脚本检查场/局标识、连续序号、结算一致性、跨局点数衔接、点数与供托守恒、最终比分/名次及实际赢家支付。重复场ID、残缺日志或不支持的格式会报错。默认把不同规则、模型权重、核心/适配代码、原生扩展和模型策略分开分组；只有显式 `--merge-configurations` 才混合。报告中保留配置身份。

诅咒V1和V2按 `curseRuleVersion` 分开，中文表及CSV明确标注；没有此字段的旧诅咒记录按V1解析。显式合并不同版本时标为 `mixed`，不会用第一组的版本冒充所有样本。独立的役种/牌型汇总遇到混合版本输入会报错，需分别分析。

## 输出

| 文件 | 内容 |
| --- | --- |
| `statistics.json` | 所有指标、分子分母、单位、公式、原始计数、名次/役种分布、配置和来源 |
| `statistics.csv` | 每个AI分组一行，22项指标为列 |
| `metric-details.csv` | 每组每指标一行，便于检查分子/分母 |
| `round-observations.csv` | 每个被选玩家每局一行，包括动作统计、支付、真实净收支及是否计入指标 |
| `sources.csv` | 每场输入是否纳入及排除原因 |
| `statistics.zh-CN.md` | 可直接阅读的中文指标表 |

CSV为UTF-8 BOM；比率数值为0至1的小数，中文表显示百分比。相同完整记录可反复重算，脚本只写指定输出目录，不改变原始牌谱。

```powershell
& $python -B -m unittest discover -s python -p test_player_statistics.py -v
```
