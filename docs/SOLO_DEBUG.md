# 单人四座调试

2026-10-25。使用现有牌桌制作独立的 `MaJiangUnity/Assets/Scenes/TableDebug.unity`。原 `TablePreview` 和 `SampleScene` 保留。

当前状态：作者在入口和组件修复后反馈初步测试没有问题，后续以此继续开发；未提供逐项验收清单。完整职责、边界与下一步见 [当前开发起点](CURRENT_BASELINE.md)。

## 操作

1. 在 Unity 打开 `Assets/Scenes/TableDebug.unity`，进入 Play，在 Game 窗口操作。也可以在 `TablePreview` 进入 Play 后，点击右上角“四座调试”或按 **F1**，直接在当前牌桌启动四座会话；不需要重建场景。键盘操作前先让 Game 窗口获得焦点。
2. 自动在 `127.0.0.1` 临时端口建立一个服务端和四个客户端，四人入房、准备并开局。无需填写 IP、固定端口或启动四个进程。
3. 面板四个座位按钮或数字键 **1–4** 切换当前控制座位。下方显示当前控制席的暗手和摸牌。查看其他席时隐藏自家副露，切回自家时恢复。牌河、桌心和玩家信息保持固定方向，其他位置暗手仍显示牌背。面板显示各席待操作、已答复、待确认或等待状态。
4. 默认自动切换到需要决策的座位，公共牌桌不旋转，下方调试文字标明正在查看哪一家手牌。取消“自动切换到待操作座位”可自由检查其他视角，再手动切回待操作席。
5. 单击选牌，再次点击出牌。独立摸牌显示刚摸到的第14张牌（副露时暗手相应减少），点击它提交摸切，点击暗手提交手切，不提供摸切按钮。立直先点“立直”，再选择宣言牌。吃、碰、杠有多个组合时，面板列出每一种使用牌，明确区分赤五与普通五。面板“全部合法操作”也包含自摸、荣和、跳过和九种九牌等选择。
6. 进入四座模式后，**F1** 或牌桌“调试”按钮收起/展开面板。点击面板不会穿透操作下层牌桌。演示模式中F1用于首次进入四座模式，切换会卸下演示的输入监听，避免两个控制器同时处理点击。
7. 默认勾选“暂停对局计时”，不会因轮流代选而超时。TCP 收发和连接维护继续工作。可以取消暂停，或点击“时间 +1秒 / +30秒”验证真实服务端超时逻辑。
8. 结算时为各席点击“确认”。多人和牌时逐页确认，最后一页才提交当前控制席的确认。四席提交后立即换局。开启计时时，服务端在结算发布 10 秒后自动确认剩余席位。暂停时可逐席查看和确认，也可用调试面板的“下一局”推进到期限。整场结束后使用“重开整场”。

开局随机分配座位，调试面板以牌局实际座位编号为准；房主身份不等于东家。所有座位均由操作者决定，不会自动跳过其他玩家的鸣牌或和牌。提交后该席输入锁定，直到服务端确认并收到新状态，防止重复点击。

公共牌桌以0号座位固定在下，依次为右侧下家、上方对家、左侧上家，按逆时针行动。下方调试文字标明手牌来自哪一家、其风位及姓名。关闭自动跟随后可固定操作一个座位。

若删除调试场景，可通过 **麻将 → 四座调试 → 创建独立调试场景** 从已保存的 TablePreview 再复制。该菜单不会覆盖已经存在的调试场景；调整布局前可以先保存 TablePreview，再创建副本。无需重新生成原牌桌。

## 接口与边界

- `LocalDebugMatch` 不依赖 Unity，串行 `Pump()` 驱动原房间、协议、日志、操作机、结算与整场生命周期，只监听本机回环地址。
- `IMatchDecisionInput` 提供当前可见状态、合法选择、提交和等待确认状态。`NetworkDecisionInput` 将一个输入绑定到一个真实客户端；前端不直接修改权威核心。未来本地输入可实现同一接口，不必重写牌桌操作。
- 调试场景组件 `MahjongTableDebug` 使用原 `MahjongTableView`，不再运行预览控制器中的对手自动摸切逻辑。IMGUI 面板仅用于开发调试。
- 调试时可切换四席读取各自私有手牌，这是同机持有四个客户端的结果；每个客户端收到的检查点仍只含本人暗手。
- 此工具验证真实回环 TCP 流程，跨设备地址、系统防火墙和实际局域网环境仍需日后验收。
