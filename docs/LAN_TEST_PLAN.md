# 局域网房间手动验收

> 当前阶段：协议v5，房间、操作、计分和整场已有自动化验证；现有牌桌/四座调试获作者初步人工反馈。本文下列步骤针对旧网络入口的多实例和跨机器专项验收，并非已经逐项通过的记录。当前起点见 [CURRENT_BASELINE.md](CURRENT_BASELINE.md)。

2026-10-25新增单人入口：打开 `Assets/Scenes/TableDebug.unity` 进入Play，或在TablePreview的Game窗口按F1/点击“四座调试”，可在一张牌桌上代选四个真实TCP客户端。默认暂停牌局计时，数字键1–4切换座位；详细步骤见 [单人四座调试](SOLO_DEBUG.md)。作者负责Unity操作验证。以下保留原多实例及跨机器验收方法。旧Client/Server空组件因场景引用暂留。

## 1. 场景与 Inspector

- 房主进程保留一个启用的 `MatchServer`。`listenIPAddress` 默认 `0.0.0.0`，`port` 默认 11111。
- 每个玩家保留一个 `NetworkControl`。房主客户端与 `MatchServer` 在同一 GameObject 时自动识别；分开挂载时将房主客户端的 `MatchServer` 字段指向服务端，并启用 `IsHost`。
- 普通客户端不要挂载或启用 `MatchServer`，`IsHost` 关闭。
- 普通客户端的 `serverIPAddress` 填房主电脑局域网 IPv4；同机多实例填 `127.0.0.1`。`serverPort` 与房主端口一致。
- `testName` 是显示名称，允许同名。旧 `testIPAddress` 仅保留场景字段兼容，不再决定连接目标或玩家身份。
- 设置每个客户端的 `clientKeyCode`。同一场景四客户端调试时可分别设数字 1、2、3、4。

已有 `NetworkControl.cs.meta` 与 `MatchServer.cs.meta` GUID 保持不变，本次未修改场景。Unity 导入新增脚本后检查新字段，旧场景不会自动填写跨机器的服务端 IP。

## 2. 调试输入

按住该客户端的 `clientKeyCode`，再按：

| 键 | 操作 |
| --- | --- |
| Z | 连接/恢复房间 |
| X | 准备 |
| C | 取消准备 |
| V | 请求开始，只有房主成功 |
| U | 主动离开房间；房主执行时关闭房间 |
| ← / → | 选择本人暗手或最后的摸牌，方括号表示所选牌 |
| Enter | 舍弃所选合法牌 |
| Space | 摸切/跳过；吃碰后按排序舍弃最大的合法牌 |
| R | 用所选舍牌宣言立直，必须满足合法条件 |
| H | 选择荣和或自摸 |
| P / J / K | 分别选择第一个合法碰/吃/杠组合 |
| D | 合法首巡九种九牌流局 |

也可通过公开方法 `ConnectToServer`、`SendReadySignal`、`SendUnReadySignal`、`StartRoomMatch`、`LeaveRoom` 或 `DisconnectAsync` 调用，不要求使用键盘调试。

操作接口为`Client.AvailableCommands`与`Client.SendCommand(command)`；选择对象已绑定产生时的本局/窗口和命令ID。调试P/J/K只取第一个合法组合，精确指定赤牌或不同吃牌组合可从该列表提交，正式组合菜单留在P6。

## 3. 验收顺序

1. 启动房主与三个普通客户端，连接后四端显示相同玩家与准备状态。
2. 使用同名玩家加入，确认玩家仍各自独立，座位不冲突。
3. 第五名玩家尝试加入，收到 RoomFull。
4. 四人准备，房间保持等待；普通玩家请求开局收到 HostOnly。
5. 一人取消准备，房主无法开局；该玩家重新准备后，房主请求开局。
6. 四端进入Playing并显示相同的新座位。各自看到自己的13张暗手，庄家另有1张摸牌，剩余可摸牌69张；普通客户端没有其他玩家暗手。只有当前有选择的玩家显示倒计时。
7. 普通玩家断开后保留令牌再连接，恢复原身份、座位、自己手牌与原阶段期限；不会因重连多获得25秒。新进程没有令牌，不能冒充原玩家。
8. 等待房间中普通玩家主动离开，可由新玩家补位；单纯断线保留非房主座位 30 秒。
9. 房主关闭服务端或退出进程，客户端显示断线；再次创建服务端可重用该端口。新房间需要新会话，普通客户端可先 `DisconnectAsync(true)` 清除原令牌。

## 4. 单局操作验收

1. 庄家用左右键及Enter手切，确认原摸牌保留在暗手，四端牌河/余牌一致；Space摸切后下一家摸牌。
2. 出现鸣牌机会时，分别选择P/J/K或Space。尚有其他合法响应者时等待其答复；吃碰后不额外摸牌，食替牌不能舍出，非法选择不会卡住牌局。
3. 有听牌时选舍牌后R；荣和窗口结束前不扣立直棒，无人荣和后才扣1000。宣言牌被碰仍成立且一发取消。
4. 有和牌机会时H手动选择；等到超时应跳过并更新对应振听，不自动和牌。无人操作的舍牌回合按期限默认摸切，吃碰后默认合法舍牌。
5. 观察每步5秒与共享20秒长考，使用部分长考后断线/重连，确认余量及原期限不恢复。
6. 暗杠后岭上阶段已翻新宝牌；明杠/加杠后新宝牌等舍牌才翻。再次开杠应立即翻前一次待翻牌。抢杠成立后不完成本次杠、不摸岭上。
7. 可一直Space摸切/跳过直至荒牌，或等待断线默认动作。四端显示一致的听牌罚符/流满、点数增减、供托、本场与公开手牌；和牌时显示役、番符、和牌张及允许公开的里牌。
8. 结算默认展示5秒再进入下一局，庄位/局数/本场应按结果变化，点数保留、长考重置20秒；上一局公开结果仍可查看，别家新局暗手不可见。
9. 在结算展示期间断线重连，恢复原结果与原换局期限；下一局不能重复支付，旧命令不能再控制新局。换局后再重连仍可查看最近结算。
10. 验证南4和止/听止、西入、西4及最终同分排名；终局后保持结果，不再发牌，房主离开关闭房间。这些少见状态可先用固定自动化牌例核对。
11. 重新连接和主动恢复期间无旧菜单操作，当前检查点安装后恢复；服务端长期静默时客户端约30秒断开并保留恢复身份。不要把静默超时误认为主动忘记会话。

自动化检查用真实 TCP 回环，未修改防火墙。不同电脑的局域网连通性需要按实际运行环境验收。

## 5. CLI 检查

在仓库根目录：

```powershell
./tests/run-core-checks.ps1
./tests/run-scoring-checks.ps1
./tests/run-network-checks.ps1
./tests/build-unity.ps1
```

网络检查仅连接 `127.0.0.1` 临时端口，结束后释放监听器与连接。受限执行环境可能需要允许本机回环 Socket。

`build-unity.ps1` 用构建时 targets 适配当前生成工程中的新/删源文件，不修改 Unity 生成的 csproj。Unity 重新生成工程后这些文件也会自然更新。
