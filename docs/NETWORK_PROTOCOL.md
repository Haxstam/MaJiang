# 局域网二进制协议 v6

> 实现日期：2026-10-24。当前包含房间、玩家可见日志/检查点、操作命令、公开结算和换局。详见 [日志同步](MATCH_SYNCHRONIZATION.md)、[状态机](STATE_MACHINE.md) 与 [计分整场](SCORING_AND_MATCH.md)。

## 1. 传输与物理帧

使用 TCP，每个物理帧固定 1024 字节。所有整数采用小端，GUID 使用 .NET `Guid.ToByteArray()` 的 16 字节布局；字符串为严格 UTF-8，长度按字节计算。

| 偏移 | 字节数 | 含义 |
| --- | ---: | --- |
| 0 | 8 | `02 48 61 78 4D 61 6A 50`，沿用 `STX HaxMajP` 标记 |
| 8 | 2 | 协议版本 `ushort`，当前为 6 |
| 10 | 2 | 消息类型 `ushort` |
| 12 | 4 | 消息编号 `uint`，从 1 开始 |
| 16 | 4 | 完整消息负载总字节数 `int`，0–65536 |
| 20 | 2 | 分片下标 `ushort`，从 0 开始 |
| 22 | 2 | 分片总数 `ushort`，1–67 |
| 24 | 2 | 当前帧有效负载长度 `ushort`，0–984 |
| 26 | 2 | 保留，必须为 0 |
| 28 | 4 | CRC-32，小端存储 |
| 32 | 984 | 负载区域，发送端未使用的部分填 0 |
| 1016 | 8 | `03 45 6E 64 50 61 63 6B`，沿用 `ETX EndPack` 标记 |

CRC 使用反射多项式 `0xEDB88320`，初值 `0xFFFFFFFF`，结果取反。计算时把 28–31 字节当作 0，其余整个 1024 字节均参与，包括填充与包尾。接收时按同样方式重新计算并比较。移除旧 MD5、时间戳、来源 IP、每帧用户名和旧 TaskID 布局。

当前 v6 增加结算确认与四席确认位图，现用消息类型为 1–17。旧客户端连接时关闭连接。

## 2. 帧读取与消息组装

- 按长度累积读满 1024 字节；一次 TCP 读取可能只有部分帧，也可能积压多个完整帧。
- 帧头尾只在规定偏移检查，不扫描负载中的第一个包尾。负载允许包含同样的字节序列。
- 帧边界处读到 0 是正常 EOF；帧内部或完整消息尚缺分片时 EOF 属于截断。
- 一条消息的分片必须连续发送，禁止分片交错。同一连接一次只分配一个最多 65536 字节的组装缓存。
- 各分片类型、消息编号、总长度一致，下标连续，每帧长度与总长度推导值完全一致。
- 组装完成前不交付消息。错误版本、类型、维度、序号或校验均关闭该连接。
- 每个方向独立编号，每次新连接从 1 开始，严格连续；`uint.MaxValue` 后回到 1，0 无效。重复帧和旧消息不重新应用。
- 读取一条完整消息的期限为 30 秒，零碎分片不会延长期限；发送整条消息也有 30 秒期限。

每连接一个读取任务、一个顺序发送任务。发送队列最多 64 条完整消息；满队列时关闭连接。收件箱最多 256 个事件，溢出时关闭来源连接。业务仅在 `Pump()` 中执行，Unity 在 `Update()` 调用它。

## 3. 字段表示

| 字段 | 编码 |
| --- | --- |
| Bool | 1 字节，只能为 0 或 1 |
| Text(N) | `ushort` 字节长度 + UTF-8 字节，最多 N 字节 |
| Guid | 16 字节；空值为全 0 |
| RoomVersion | `long`，非负 |
| Seat | 1 字节，0–3 |
| MatchType | 1 字节，使用现有四人东/南枚举值 |
| RoomPhase | 1 字节，0 等待、1 对局中、2 已关闭 |

每种消息必须恰好解码完所有负载。截断、非法 UTF-8、非法布尔值或额外尾随字节关闭连接。

## 4. 房间消息

| 值 | 类型 | 方向 | 负载 |
| --- | --- | --- | --- |
| 1 | Join | 客户端→服务端 | `Text(48) Name`、`Guid ResumeToken`、`Guid HostProof` |
| 2 | Joined | 服务端→客户端 | `Bool Accepted`、`Text(96) Reason`、`Guid RoomId`、`Guid PlayerId`、`Guid ResumeToken` |
| 3 | RoomState | 服务端→客户端 | 见下节 |
| 4 | SetReady | 客户端→服务端 | `Bool Ready` |
| 5 | StartMatch | 客户端→服务端 | 空 |
| 6 | Leave | 客户端→服务端 | 空 |
| 7 | Result | 服务端→客户端 | `uint RequestMessageId`、`Bool Accepted`、`Text(96) Reason` |
| 8 | Heartbeat | 双向 | 客户端→服务端为空；服务端→客户端为long进程单调时钟毫秒 |
| 9 | RequestState | 客户端→服务端 | 空 |
| 10 | SetMatchType | 客户端→服务端 | `byte MatchType` |
| 11 | MatchSnapshot | 服务端→客户端 | 指定玩家的最新可见检查点 |
| 12 | MatchLog | 服务端→客户端 | 本局身份、最新序号及最多16条可见裁定记录 |
| 13 | MatchAck | 客户端→服务端 | 两个Guid局身份、int局代数、long最后已应用序号 |
| 14 | RequestMatchSync | 客户端→服务端 | 同MatchAck，再加Bool强制检查点 |
| 15 | MatchCommand | 客户端→服务端 | Guid MatchId、Guid RoundId、int RoundGeneration、long PhaseId、Guid CommandId、可选动作 |
| 16 | MatchCommandResult | 服务端→客户端 | Guid CommandId、Bool Accepted、Bool UsedDefault、Text(96) Reason、long PhaseId、long Sequence |
| 17 | ConfirmSettlement | 客户端→服务端 | Guid MatchId、Guid RoundId。服务端按当前连接的座位确认，回应 Result |

`Result`对应房间请求的当前连接消息编号。操作使用独立`MatchCommandResult`，CommandId按认证座位在本局去重，重连仍有效，不把帧序号当成完整的对局操作编号。相同命令重试需重新发送为一条正常递增编号的网络消息；重复物理消息编号仍是协议错误。

可选动作编码为Bool存在标记；存在时依次为byte PlayerAction、byte SelfNumber、byte TargetPlayerNumber、byte所选手牌数（最多4）、各张可选牌、可选TargetTile。可选牌为Bool存在，非空再写byte Color和byte牌号（0表示该花色赤五）。列表成员不可为空。结构合法但当前规则非法的命令按默认动作裁定；结构损坏仍关闭来源连接。

### RoomState

头部按顺序为：`Guid RoomId`、`long Version`、`byte Phase`、`byte MatchType`、`byte MemberCount`。

每名玩家按顺序为：`Guid PlayerId`、`Text(48) Name`、`byte Seat`、`Bool Connected`、`Bool Ready`、`Bool IsHost`。

最多四人，座位与玩家 ID 不重复，最多一个房主。恢复令牌、房主接入凭据和连接对象不出现在公开快照中。房间版本只在状态变化时递增；客户端安装版本更高的同房间快照。

## 5. 会话与房间行为

- 名称允许重复；身份由服务端生成的玩家 ID 与随机恢复令牌决定。
- 房主的接入凭据由本地服务端生成，仅交给本地房主客户端。第一个远程访客不会自动成为房主。
- 首次加入时恢复令牌为空；恢复时提交原令牌，重新绑定原座位和玩家 ID，旧连接随即失效。
- 等待房间中断线清除准备状态；非房主座位保留 30 秒，过期后可被新玩家加入，旧令牌失效。房主座位保留至房间关闭。
- 主动离房在等待阶段立即释放普通玩家座位；开局后只断开该玩家、保留座位。房主主动离房关闭整个房间。
- 四人连接并准备后仍等待房主发送 StartMatch。开始时随机分配起家座次，向所有客户端同步新座位。
- 房主可在等待阶段设置四人东/南模式，改变模式清除所有准备。其他已确认规则参数仍按固定首版预设，完整规则配置消息在 P3 扩展。
- 对局开始后拒绝新玩家顶替，已有玩家可恢复连接。恢复不重置对局期限或长考，断线照常超时与默认动作。
- 每秒心跳，只检查活性，不携带完整对局日志。未完成加入的连接最多保留 10 秒，服务器最多同时保留 16 个 TCP 连接。

## 7. 结算字段

裁定状态末尾为 `long NextRoundMilliseconds` 与 `byte SettlementConfirmations`。前者是服务端自动确认的期限，0 表示当前无等待期限。确认位图低四位对应绝对座位 0–3，四家确认后为 15，开始新局后归零。检查点在本人手牌之后携带可选公开结算。增量在本人手牌变化区之后携带 Bool 结果变化标记，仅变化时写可选结果。可选结果为 Bool 存在、存在时 int 字节长度及最多 8192 字节负载，完整消息按通用机制分片。

结算编码顺序为：Guid RoundId、int局代数；byte结束原因/和牌者位图/听牌位图/流满位图；各4个int的前点数、后点数、增减；两个int供托前后；Bool连庄、Bool终局；byte下局风/局/庄、int下局本场；4个byte排名座位；byte和牌/流满人数及明细；byte公开手牌人数及明细；有显式计数的里指示牌列表（最多5）。

每名和牌者为byte本人/来源/包家加1（0无包家）；可选和牌张；4个int的番/符/基本点/实际役满倍数；byte役数（最多48），各役为byte枚举、int番、int役满倍数；4个int逐座位支付。每个公开手牌为byte座位、最多13张暗手、可选摸牌及最多4个面子，复用同一牌值与面子编码。

解码验证边界、座位唯一性、排名排列、点数增减及含供托总账。结果局代数不得晚于接收视图，相同代数必须同RoundId。结算仅携带按规则已公开的手牌/里牌；普通私有手牌投影仍不携带别家暗手。
