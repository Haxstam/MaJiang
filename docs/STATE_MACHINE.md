# 对局操作状态机

> 2026-10-24：P3b已接通共享查询、玩家命令、响应窗口和超时。P4现已连接结算和下一局，当前协议v5，详见 [计分与整场](SCORING_AND_MATCH.md)。

## 1. 代码与职责

`AuthoritativeMatchMachine`是唯一操作推进入口，持有`MatchJournal`中的完整核心；网络先从恢复会话确定座位，再提交命令。P5已删除ActionDeduce、旧候选字典和旧规则/DFS，回归检查改用现用入口，见`CLEANUP_AND_RECOVERY.md`。

`MatchActionRules.GetActions`在客户端和服务端共用，输入公共状态、本人手牌和`MatchActionContext`，无副作用，不访问其他玩家暗手。客户端通过`VisibleMatchState.GetAvailableActions`调用；服务端用自身权威状态重新生成合法选择，不能信任客户端自报的合法性。

`HandAnalysis`枚举34种真实牌及普通/七对子/国士牌型，提供听牌与立直暗杠分解比较。役合法性现已调用统一`RiichiScoring`，宝牌不提供役，不维护另一套布尔役判断。运行时仍使用已确认的一番缚、无古役预设。

## 2. 操作窗口

| 值 | MatchOperationStage | 行为 |
| --- | --- | --- |
| 0 | AwaitingDraw | 日志初始基线，初始化完成后由状态机摸牌 |
| 1 | Discard | 当前玩家手切/摸切、自摸、立直、暗杠/加杠或九种九牌 |
| 2 | DiscardAfterCall | 吃碰后必须合法舍牌，不额外摸牌，禁止现物与筋食替 |
| 3 | DiscardResponse | 舍牌后收集荣和、吃碰大明杠或跳过 |
| 4 | AddedKanResponse | 加杠未成立，收集抢杠荣和或跳过 |
| 5 | ClosedKanResponse | 暗杠未成立，仅允许国士抢暗杠或跳过 |
| 6 | RoundEnded | 固定结束原因、和牌者位图及目标牌，不再接受操作 |

旧`StageType`仍作为核心粗阶段同步，实际命令有效期以`MatchOperationStage`和`PhaseId`为准。每次新窗口递增PhaseId；同一响应窗口的其他人答复会增加日志序号，但不会更换PhaseId。结束原因`RoundOutcomeKind`区分荣和、自摸、荒牌、九种九牌、四风、四家立直和四杠；流满及支付由P4在荒牌结算时判断。

## 3. 请求、回执与默认动作

命令携带MatchId、RoundId、RoundGeneration、PhaseId、CommandId及具体动作。`CommandId`为GUID，与TCP每连接消息编号分开。客户端`AvailableCommands`生成时绑定当时局身份和窗口，`SendCommand`不会把旧菜单的选择重新绑定到新窗口。

- 服务端按认证座位及CommandId缓存本局已消费命令，最多4096条。相同字节的原请求重试返回原回执，不再次执行；同ID修改内容返回CommandIdReused。恢复连接后身份不变，仍可使用原ID重试。
- 错局、旧窗口、冒用座位、已经答复及无操作机会的请求仅拒绝，不消费当前机会。
- 对当前仍待操作玩家，结构合法但规则非法的响应按Skip；自己回合的非法选择按默认舍牌。回执Accepted=false、UsedDefault=true，原因明确区分这两种情况。
- 默认摸切；吃碰后按`Tile.CompareTo`选择最大的合法手牌：万、筒、索、字牌，牌号升序，同种普通五在赤五前。食替限制仍生效。
- 编码损坏、非法枚举、牌值或超长字段仍属于协议错误，关闭来源连接；这不等同于已成功解码的非法规则选择。
- 回执只确认处理结果和裁定后窗口/日志位置；客户端通过日志安装实际状态，不根据回执本地扣牌。

## 4. 计时与响应裁定

服务端单调毫秒时钟可注入，必须与日志共用时间基准。每窗口5秒基本时间，超过部分消耗本局共享20秒长考；新摸牌、鸣牌、杠响应不会重置长考。P4新建下一本场状态机时才重置。检查点按当前时钟取长考余量，重连不恢复已耗时间。

每名实际有选择的响应者独立计时；没有任何荣和/鸣牌选择者自动完成响应，不等待25秒。响应者选定后冻结其长考余量，剩余人继续计时。非行动玩家的本人期限为0。

每次`Pump`及`Submit`先执行`Tick`。时间恰好到期限时，超时先于新命令处理：需要出牌则默认舍牌，响应则跳过，不自动和牌。晚到旧请求不会再次消费新窗口。

等待所有有选择者答复或超时，再统一裁定：全部荣和者优先，允许双响/三响；无荣和时碰/大明杠优于吃，同级按放铳者下家方向最近者优先。先到的吃/碰包不能提前阻止后到的荣和。未完成收集时不公布玩家具体选择，仅同步各人自己的已答复状态。

## 5. 规则时点

- 立直宣言先舍牌并开放荣和窗口；无人荣和后才扣1000、增加供托、设置立直/两立直/一发。宣言牌被吃碰仍确认立直，鸣牌同时取消一发；宣言牌被荣和不扣棒。
- 立直后仅摸切、自摸及新摸第四张且所有分解/等待均不变的暗杠。立直可处于舍牌振听。
- 舍牌振听根据全部牌型等待与自己牌河重算；见逃可成型但无役的舍牌也标记同巡振听。自己的下一次摸牌清除同巡位，立直见逃位保留至本局结束。
- 暗杠/加杠先开放抢杠窗口，再修改面子、杠数及牌山。抢杠成立时仅从来源手牌移除被和的那张，不完成本次杠、不摸岭上、不翻本次宝牌。
- 暗杠新宝牌与岭上摸牌一起进入后续日志；大明杠/加杠新宝牌在岭上后舍牌时公开。再次声明杠时立刻翻前一次待翻宝牌，即使新杠随后被抢；当前明杠/加杠岭上和牌不计仍待翻的新宝牌。
- 可摸牌数为0时禁止吃碰杠，仍先开放荣和窗口再荒牌流局。用户补充确认：杠后余牌归0时，岭上摸牌后的舍牌允许仅以河底捞鱼荣和。
- 四家立直、四风、四杠均保留舍牌荣和优先。不同玩家的第四杠允许岭上自摸及随后舍牌荣和，之后才四杠散了；同一人四杠不散了，均禁止第五杠。

## 6. 同步与本阶段边界

命令造成的牌区、阶段、本人振听/已答复/余时及食替限制均写入既有可见裁定日志。正常同步不下发完整菜单；初始化、重连或补齐失败仍使用检查点。扩展字段和命令消息使帧版本升为4，v3客户端须同步升级。

P3b原61项检查在P4扩展至69项，P5恢复边界后共75项。另有42项计分、21项核心及Unity CLI编译通过。

P4现已接通支付、流满/罚符、里牌公开、连庄下庄、5秒展示后下一局及最终排名，见`SCORING_AND_MATCH.md`；MatchSession负责整场生命周期，单局操作机仍只负责本节所述操作。当前网络检查75项、计分42项，Unity Editor多实例和跨机器验收仍按`LAN_TEST_PLAN.md`执行。
