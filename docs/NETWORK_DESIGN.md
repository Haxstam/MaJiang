## 3. 已实现流程

1. 房主启动监听，生成本房间的房主接入凭据。
2. 四个客户端通过同一协议加入；房主客户端提交本地凭据，普通访客不会因先加入而成为房主。
3. 服务端分配玩家ID、恢复令牌和等待座位；公开快照只发送公开信息。
4. 准备/取消准备更新房间状态并广播。四人准备后仍等待房主开始。
5. 房主开始时随机确定起家座次，纯服务端创建完整MainMatchControl和日志基线，记录庄家首摸并分玩家发送可见检查点。
6. 客户端本地查询操作并提交当前窗口命令；服务端认证、去重与重新校验，收集响应后裁定，变化通过可见日志同步。
7. 普通客户端断线后继续计时与默认动作，原身份与座位可恢复；新连接接管时旧连接失效，当前期限/长考不重置。
8. 房主结束房间时关闭监听与所有连接，等待后台任务退出，端口可重新使用。

等待阶段非房主断线保留30秒后清退；开局后永久保留该场座位，直到房间结束。名字不作为身份，不发送令牌到公开玩家列表。

## 4. 日志同步与操作

客户端使用公共牌局信息、自己手牌和必要私有状态计算操作，服务端调用共享规则进行最终校验。默认不发送所有合法操作列表。

正常权威变化发送动作与裁定增量日志；初始化、无法补齐或重连时发送可见检查点。按序应用后得到相同可见状态。心跳附带服务端单调时钟，旧日志不能退还已流逝的时间。当前帧支持64KiB有界消息并原子组装，完整牌山、未公开里宝牌、其他玩家暗手和随机种子不进入客户端消息。

游戏请求使用MatchId/RoundId/局代数/阶段编号与独立CommandId；按认证座位缓存原回执。相同窗口其他人答复不使本人的选择过期，错局/旧窗口不消费当前机会，当前非法规则选择走默认动作。帧编号不替代跨连接的游戏命令编号。客户端从检查点按序应用服务端结果，本地规则仅查询选项。具体行为见状态机文档。

原混合日志链路已替换为独立日志服务。现在包含番符、支付、结果展示、下一局和最终排名；重连恢复当前本局与最近公开结算。旧计分器、旧动作推演/候选字典、旧听牌DFS及512字节编码均已删除，见`CLEANUP_AND_RECOVERY.md`。前端设计按作者要求等素材到位后再进行。
