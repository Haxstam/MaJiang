# 计分、结算与整场推进

> 2026-10-24：P4已实现首版预设的计分、支付、换局和终局。核心21项、计分42项、网络/同步/整场75项检查通过；Unity CLI编译通过。Editor多实例及跨机器运行仍待验收。

## 1. 统一计分入口

`RiichiScoring.Evaluate(WinContext)`是唯一实际计分器。上下文显式传入公共牌局、本人暗手、和牌张、自摸/抢杠/首摸标记及允许公开的里宝牌。暗手列表不重复包含和牌张，副露与暗杠从本人面子列表读取。不使用静态当前对局，也不修改输入。

`HandAnalysis`继续提供34牌种的普通、七对和国士牌型枚举；原独立的一番缚判断已收敛为调用统一计分器。客户端菜单和服务端实际和牌因此使用同一役判断，不再维护两份役种逻辑。国士抢暗杠仍先限制为国士牌型。

旧`FanCalculator`在计算符之前使用fu=0计算基本点，并依赖静态状态；`RonData`还存在上下文字段遗漏。已确认三者无代码/场景引用后删除`FanCalculator`、`RonData`、`RonPoint`及meta，替换为`WinContext`、`ScoredHand`、`ScoredYaku`。作者原实现完整保存在本轮240文件恢复基线中。

## 2. 番符与最高得点

- 同时枚举普通、七对、国士，并对普通分解逐个枚举和牌张属于雀头或哪一组暗手面子。荣和完成的刻子按明刻计算符及三/四暗刻，但不因此取消门清荣和10符。
- 普通符先计算底符20、刻杠、役牌雀头、单骑/边坎等待、门清荣和10、自摸2，再十位进位；七对固定25符，平和自摸固定20符，副露平和型荣和30符。双风雀头4符，座风相对于当前庄家计算。
- 一杯/两杯不重复计；纯全/混全、清一色/混一色、大小四喜等按互斥规则取对应项。七对可与混老头等复合，不叠加对对和。
- 先满足最低役番，再计算宝牌、赤牌和里宝牌；宝牌不提供役。里宝牌仅立直和牌计入，每张实际公开的表指示牌对应一张里指示牌，延迟待翻的杠宝牌不提前计入。
- 岭上自摸不叠加海底；岭上后余牌为0的舍牌仍允许河底唯一役，遵从用户补充决定。抢加杠可作为唯一役。
- 4番30符、3番60符不切上满贯。5番满贯、6–7跳满、8–10倍满、11–12三倍满、13以上累计役满封顶单倍。
- 实际役满可复合；国士十三面、四暗刻单骑、纯正九莲、大四喜为双倍。实际役满忽略普通役和宝牌，结果单独存储倍数。
- 对每个候选结果计算不含本场供托的实际和牌总收入，取最高值；支付逐笔百点进位，不能只比较番数。

## 3. 支付与流局

`RoundSettlement.Calculate`是纯函数，生成完整结算结果，不直接修改核心。`MatchSession`核对总账后一次提交点数和供托，再记录裁定日志。

荣和由放铳者支付各和牌者的基本支付。双响/三响全部成立；本场加点及供托仅归放铳者下家方向最近者，跨座位0的顺序也按相对距离计算。庄家在和牌者中则连庄。

自摸庄家三家各付基本点×2；子家由庄家付×2、其他两家各付×1，各笔分别进百。普通本场每位支付者加100。

包牌仅大三元/大四喜：从按成立顺序保存的面子判断最后一组所需面子的来源；碰/大明杠按来源包牌，加杠保留原碰的位置和来源；最后由暗杠完成不包牌。之前已经公开的暗杠可计入所需面子数。自摸包家承担该责任役满全部，荣和与放铳者各半，同一人全付；复合中其他役满正常支付。大四喜的责任部分覆盖双倍；本场由包家承担，无大明杠包/四杠子包。

荒牌自动以真实牌型等待判听牌，无役也听。1/2/3人听牌时分配总计3000罚符，0/4人听牌无转移；庄听连庄，否则下庄，均本场加1、供托留场。公开实际听牌者手牌，不公开未听者手牌。

流满使用作者原定义：本人河非空、全幺九、未被别家鸣取；本人鸣牌不取消流满。允许多人同时成立，各按满贯自摸支付本场，无听牌罚符，供托留场；仍按庄家实际听牌连庄/下庄、本场加1，不能把流满者直接视为和牌连庄。

途中流局不作罚符，连庄、本场加1、供托留场。九种九牌公开宣告者手牌，其余途中流局不额外公开暗手。所有分支均验证“点数合计+供托×1000”守恒。

## 4. 终局优先级

1. 全部和牌/包牌/供托支付完成后判断负分击飞；中间某笔支付出现负分但后续收入恢复时不提前击飞。恰好0点继续。
2. 南4庄家和牌或听牌流局，结算后第一且至少30000自动结束。用户本轮明确：南4多人荣和且庄家也和牌，成为第一达标时仍自动和止。
3. 南4应下庄时有人达30000结束，否则进入西1。西入后有人达30000结束；多人荣和含庄家的连庄优先于该西入达标终局。
4. 西4下庄必结束，不北入；未触发其他终局条件时西4允许连庄。途中流局保持连庄，不被此前西入达标状态单独中断。
5. 最终同分按起家座位0、1、2、3优先；尾供托全部归第一。首版显示最终持点和名次，不计算段位积分/顺位分。

东风配置使用同样逻辑，正常末场为东、延长场为南；本轮主要验收四人东南预设。

## 5. 结果同步及下一局

`RoundSettlementResult`包含本场身份、结束原因、和牌/听牌/流满位图、前后点数与增减、前后供托、各和牌者的役/番/符/基本点/责任人/四家支付、允许公开的手牌与里指示牌、下一局参数及最终排名。

结果单独存于`VisibleMatchState.Settlement`，不把别家已公开旧手牌写进新局私有手牌。P5已移除公共状态里牌空槽，未公开牌面只在服务端王牌中，允许公开的里牌只进结算。增量仅在结果身份改变时带新结果，普通打牌不重复整份结果。

`MatchSession.Tick` 在操作机结束后结算一次。服务端以绝对单调毫秒记录 10 秒确认期限，四席提前确认即可换局。断线期间时间继续，到期自动补齐确认。展示期间重连恢复原结算、点数、确认位图及原期限。

确认完成且未终局时保留点数和供托，应用下一局风位、局数、庄位与本场，重建牌山和手牌，清理立直、振听和待翻宝牌，重置本局 20 秒长考。换局生成新 RoundId 和递增代数，记录庄家首摸为 0。上一局公开结果继续保留供查看与重连。

终局时不自动开新牌局，保留结果及排名。房间仍保持Playing以便查看/重连，房主离开结束房间；整场是否结束读取Settlement.MatchEnded。

网络帧使用 v6，消息类型 17 提交本局结算确认。检查点和增量同步确认位图，旧客户端需要同步升级。见 [网络协议](NETWORK_PROTOCOL.md)。
